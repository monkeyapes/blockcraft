# Blockcraft native client

A Rust program with its own window and GPU renderer (wgpu + winit), replacing
the webview shell in `desktop/`. The goal is the same game, running natively.

## How it fits with the TypeScript game

- **Content comes from TypeScript.** `tools/export-native.ts` renders the
  texture atlas with the same recipes the web game uses and writes it, plus
  the block and item data (ids, names, textures, flags, shapes), into
  `native/assets/`. The native game loads those files, so art is drawn once.
  Re-run the export whenever blocks, items or textures change, and commit the
  result: the game compiles both files in, so a Rust build never needs Node.

      npx tsx tools/export-native.ts

- **World generation is ported exactly** (`native/worldgen`), so a seed makes
  the same world in both, and a native client can join the existing server,
  which only ever sends edits. Until the port lands, `worldgen` returns a flat
  test world; the game uses only its public API (`generate_chunk`,
  `voxel_index`, `CHUNK_X`/`CHUNK_Z`/`WORLD_Y`), so the real terrain drops in
  with no change here.

## Layout

- `worldgen/` -- the world generator, a library with parity tests against
  chunks generated by `shared/src/terrain.ts`.
- `game/` -- the executable:
  - `content.rs` reads `content.json` into a dense block table.
  - `world.rs` holds loaded chunks and per-column sky heights.
  - `jobs.rs` is the worker pool: chunk generation and meshing run on
    background threads, nearest-to-the-player first.
  - `streaming.rs` decides what to load, mesh and unload around the player,
    and tells the renderer what changed.
  - `mesher.rs` turns 16x16x16 sections into quads (a port of
    `client/src/mesher.ts`).
  - `player.rs` is movement, collision and the block raycast (a port of the
    core of `client/src/player.ts`).
  - `render.rs` + `shaders.wgsl` draw the world, the outline and the HUD;
    `hud.rs` builds the HUD, with its own 3x5 pixel font.
  - `game.rs` ties it together without a window; `app.rs` is the window.
  - `stress.rs` is a synthetic busy world for benchmarks (`--stress-world`),
    not a terrain generator for play.

## Phases

1. Core (this): window, renderer, meshing with the real block shapes,
   textures from the exported atlas, world streaming on worker threads,
   walking/flying, breaking and placing, true fullscreen.
2. Gameplay: lighting (full propagation, torches), inventory and crafting,
   saving, multiplayer.
3. Content: mobs, machines, combat, farming, the rest of the packs.

## Building and running

    cd native
    cargo run -p blockcraft-native --release
    cargo test -p blockcraft-native

Release builds on Windows have no console window; pass `--log FILE` to keep
the log.

| Option | Meaning |
| --- | --- |
| `--seed N` | World seed (default 20240, so runs match). |
| `--distance N` | Render distance in chunks (default 12). |
| `--size WxH` | Window (or screenshot) size, default 1280x720. |
| `--no-vsync` | Uncapped frame rate, for measuring. |
| `--threads N` | Worker threads (default: cores - 1, at most 8). |
| `--assets DIR` | Read `content.json` and the atlas from a folder instead of the built-in copies -- to try a fresh export without rebuilding. |
| `--screenshot PATH` | No window: load the world, time it, render one frame offscreen to a PNG, and exit. |
| `--camera X,Y,Z,YAW,PITCH` | With `--screenshot`: where to look from. |
| `--showcase` | With `--screenshot`: build a row of sample blocks and a roofed shelter at the spawn first. |
| `--stress-world` | Play the synthetic benchmark world instead of `worldgen`. |
| `--autopilot` | Once loaded, fly straight ahead at full speed (a streaming benchmark). |
| `--run-for SECONDS` | Quit after this long. |
| `--log PATH` | Also write the log to a file. |

## Performance

Measured on a 4-core PC with a GTX 1050 Ti (Vulkan), render distance 12,
1280x720, release build:

- Flat test world: the 577 chunks around the spawn generate and mesh in
  0.2 s (about 3,000 chunks/s on three workers); a frame costs 0.5 ms.
- `--stress-world` (hills, caves, lakes, trees; about 1.1M quads loaded, 70 MB
  of vertex data): 0.7 ms per chunk to generate and 0.8 ms per section to mesh
  on a worker, about 800 chunks/s; a frame draws ~650 of ~2,000 sections
  (0.35M quads) in 1.7 ms. Flying at full speed (`--autopilot --no-vsync`),
  streaming about 50 new chunks a second: 1.3 ms median frame, 2.4 ms p99,
  under 6 ms worst.

Things that keep it there: worker threads never touch live data (a mesh job
gets `Arc` snapshots of the 3x3 chunks it needs); a 16-byte vertex; one shared
quad index buffer and per-section origins as instance data, so a section is
one bind and one draw; frustum culling and front-to-back sorting; empty
sections never meshed; and mesh uploads capped at 2 ms a frame, with edits
first, so crossing a chunk border never hitches.

## `content.json`

Written by `tools/export-native.ts`, read by `game/src/content.rs`. Pretty
JSON, with number lists kept on one line so the file reviews well in a diff.
`format` is bumped whenever a change would make an older reader misread the
file; the game refuses a format it does not know.

```jsonc
{
  "format": 1,
  "atlas": {
    "file": "atlas.png",   // beside content.json
    "grid": 21,            // tiles per row and per column (the atlas is square)
    "tile_px": 64,         // pixels per tile edge
    "size": 1344,          // atlas edge in pixels = grid * tile_px
    "tiles": ["apple", ...] // tile names in slot order (slot = row * grid + col)
  },
  "blocks": [ /* one entry per defined id, 0-255; missing ids are unknown */
    {
      "id": 37,
      "name": "Torch",
      "textures": [409, 409, 409], // atlas slots: [top, bottom, side]
      "icon": 409,                 // slot for inventory icons
      "solid": false,              // collides with bodies
      "opaque": false,             // hides neighbours' faces, blocks light
      "translucent": true,         // drawn in the blended pass
      "liquid": false,
      "breakable": true,
      "light": 14,                 // emitted light, 0-15
      "hardness": 0,               // relative time to break, 1 = dirt, 0 = instant
      "replaceable": false,        // placing into it overwrites it
      "climbable": false,          // ladders
      "slipperiness": 0,           // 0 = grips; ice is 0.9
      "speed_factor": 1,           // walking pace multiplier (soul sand 0.55)
      "bounce": 0,                 // fraction of landing speed returned
      "cross": null,               // or { "height": 1, "inset": 0.1 } for plants
                                   // drawn as two crossed planes
      "shape": {                   // null for a full cube
        "visual":    [{ "min": [0.4375, 0, 0.4375], "max": [0.5625, 0.625, 0.5625] }],
        "collision": [ ... ],      // what bodies bump into (only if solid)
        "selection": [ ... ],      // what the cursor hits and outlines
        "dynamic": false           // the real shape depends on neighbours
                                   // (fences, panes, doors); the boxes above
                                   // are how it stands alone
      }
    }
  ],
  "items": [                       // non-block items, ids from 256
    { "id": 256, "name": "Stick", "icon": 388, "stack": 64, "places": null }
  ]
}
```

Boxes are in cell-local block units, 0..1 on each axis (a model may reach a
little outside its cell). A box may carry `"tex": [top, bottom, side]`
overriding the block's own textures for that box. The mesher maps a box's
texture to its real extent, so a slab's side shows a slab's share of the tile
rather than the whole tile squashed.

Air (id 0) draws nothing whatever it lists; an id with no entry reads as air,
so a world saved by a newer build stays walkable.
